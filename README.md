## 1 프로젝트 설명
TV나 유튜브 등에서는 특정 요리를 위한 레시피를 알려주는 컨텐츠가 증가했으나, 막상 집에 있는 재료와 도구로 만들기에는 어려움. 이에 냉장고의 남은 재료로 간편하게 조리 가능한 레시피를 알려주어 실생활에 도움되는 레시피 추천 프로그램을 지식그래프를 이용하여 구현.

### 1-1 팀명 및 팀원 역할

김유건: 데이터 수집 및 전처리
홍기표: 데이터 전처리, 스키마 설계
이승재(팀장): 스키마 제약조건 설정

### 1-2 GRAND RULE
30분마다 작업내용 상호 확인.

과도한 AI 의존 지양.

고난도 파트는 상호 질문을 통해 해결.

이해 또는 코드 작성이 너무 힘들면 AI에게 질문.

팀원에게 먼저 질문.

### 1-3 기간 및 기반 프로그램 등
프로젝트 기간: 2026년 9월 16일 ~ 9월 18일

기반프로그램: gpt-5.6-luna, streamlit, Neo4j

재료와 레시피 사이의 INGREDIENT 관계에는 다음 속성을 저장.
- usage_key: 레시피와 재료 사용 항목을 구분하기 위한 식별자
- quantity: 재료 사용량
- unit: 단위
- role: 식재료 또는 양념
- preparation: 손질 정보
- raw: 원본 재료 표현
- amount_text: 원본 수량 표현
- source_group: 원본 데이터의 재료 그룹
이를 통해 동일한 재료가 여러 레시피에 사용되는 경우에도 레시피별 사용량과 재료 역할을 구분 가능.

. Neo4j 적재 과정
Neo4j 적재는 다음 순서로 수행하였다.
- 전처리된 레시피에서 대분류, 중분류, 레시피, 재료 정보를 분리하였다.
- 각 노드와 관계에 대한 중복 여부를 검사하였다.
- Neo4j에 노드별 고유성 제약조건을 생성하였다.
- MERGE를 사용하여 대분류, 중분류, 레시피, 재료 노드를 생성하였다.
- HAS_TYPE, HAS_DISH, INGREDIENT 관계를 연결하였다.
- 대량 데이터 처리를 위해 200개 단위로 배치 적재하였다.
- 적재 전후의 노드 및 관계 개수를 비교하여 데이터 누락 여부를 검증하였다.

노드의 중복 방지를 위해 다음 속성에 고유성 제약조건을 설정.
- DishGroup.name
- DishType.key
- Dish.recipe_uid
- Ingredient.name_normalized

### 5-1 재료명 정규화 결과
재료명 정규화 과정에서는 별칭 통합, 불필요한 설명 제거, 조리 준비 상태 분리, 수량 및 단위 표준화가 적용됨.

- 고추가루 → 고춧가루
- 후추가루 → 후춧가루

정규화 과정에서 총 1,581건의 재료명이 변경되었고, 또한 4,552건의 재료 구성요소가 검토 대상으로 분류되었으며, 이 중 재료명 관련 검토 항목은 4,546건, 수량 관련 검토 항목은 6건.
Ingredient 노드는 총 3,367개이며, 이 중 2,215개는 단일 레시피에서만 등장하는 singleton 재료명이다. 다만 singleton이라는 사실만으로 오분류나 정규화 오류라고 판단할 수 없으므로 별도 검수 대상과 구분해야 함.

### 5-2 원문 근거 검증
INGREDIENT 관계 42,118건을 대상으로 자동 근거 검사를 수행.
- 원본 재료 구성요소와의 정확한 일치율: 100%
- 레시피 본문 내 evidence 문자열 포함율: 25.27%
원본 재료 구성요소와의 정확한 일치율이 100%라는 점에서, 생성된 관계의 evidence가 입력 데이터의 재료 항목에서 유래했음을 확인.
반면 본문 텍스트 내 문자열 포함율은 25.27%로 상대적으로 낮음. 본문에 재료명이 그대로 반복되지 않거나, 표기 방식이 다르거나, 재료 정보가 별도 구조화 필드에만 존재하기 때문으로 추정. 따라서 이 수치는 의미적 근거의 정확도나 관계의 정답률을 직접 의미하지 않으며, 의미적 근거 적합성은 별도의 사람 검수가 필요하다.

### 5-3 GDS 분석 결과
GDS 분석은 DB와 payload 비교가 통과된 경우에만 수행하도록 설계되어 있다. 이번 실행에서는 DB 검증이 실패했기 때문에 GDS 분석은 안전상 차단됨.
따라서 이번 실행에서는 다음 분석 결과를 제공하지 않음.
- Ingredient PageRank 상위 목록
- 레시피 유사도 기반 커뮤니티
- Louvain 커뮤니티 분석 결과
DB를 검증 전용 상태로 정리하고 payload와 일치시킨 뒤 GDS 분석을 재실행해야 한다.
